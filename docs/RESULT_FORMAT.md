# Контракт результатов для участников команды

Текущий формат: `schema_version = 1`. JSON в `results/` — основной источник;
`metrics.csv` — плоское представление статистики, не оценка правильности смысла.
Файлы `*.response.json` — сырые ответы SDK; оценщик должен читать только JSON
результатов без этого суффикса и сопоставлять их с `manifest.json`.

| Поле результата | Содержание |
|---|---|
| `result_id` | Уникальное имя результата внутри запуска |
| `lecture_id`, `lecture_name` | Лекция, из которой получен конспект |
| `lecture_snapshot` | Путь к тексту относительно папки запуска |
| `source_sha256` | SHA-256 текста снимка в UTF-8 |
| `method`, `repeat` | M1/M2 и номер независимого повтора |
| `model`, `model_version` | Запрошенная модель и версия из ответа сервера |
| `prompt`, `prompt_sha256` | Полный отправленный текст и его хеш |
| `generation_config` | Общие явно заданные параметры генерации |
| `summary` | Итоговый текст; null, если ответа не было |
| `status` | success / truncated / blocked / empty / error / interrupted / dry_run / running |
| `finish_reason` | Причина завершения от API, если была |
| `usage` | Поля SDK в snake_case: prompt_token_count, candidates_token_count, thoughts_token_count, total_token_count и другие |
| `attempts` | Номер, время начала, длительность и ошибка каждой попытки |
| `elapsed_seconds` | Время результата вместе с ожиданиями |
| `api_seconds` | Суммарное время API-попыток |
| `source_words`, `summary_words` | Число слов по разделению пробелами |
| `summary_to_source_word_ratio` | summary_words / source_words |
| `within_word_limit` | Соблюдение требования по длине; null без ответа |
| `error`, `error_code` | Описание и HTTP-код ошибки, если есть |

Для оценки качества не смешивайте success с dry_run, error, blocked, empty,
truncated и interrupted. Частоту неудачных запусков считайте отдельно и указывайте
в отчёте; исключение неудач без учёта их количества исказит сравнение методов.
Превышение словесного лимита отмечено отдельно и не приводит к обрезке текста.

Для будущих M3/M4 сохраняйте все этапы и попытки; итоговый `usage` должен учитывать
все известные расходы метода, а `summary` — именно конечный объединённый конспект.
Каждый этап должен связывать сведения с идентификаторами исходных блоков.
Проверка в M4 работает с исходником, без доступа к эталонной разметке эксперимента.

Оценщик третьего участника читает `summary` и снимок лекции, затем сопоставляет
конспект с отдельным эталоном. Результат оценки хранится отдельно от генерации,
чтобы смена оценщика не требовала новых запросов для конспектирования.
