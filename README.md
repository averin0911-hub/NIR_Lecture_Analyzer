# Анализатор текстовых лекций — эксперимент M1/M2

Консольная программа для вашей части НИР: запускает обычное и структурированное
конспектирование на **одной модели Gemini**, сохраняет конспекты и статистику.
В проект включён демонстрационный текст об алгоритме Дейкстры.

## Быстрый запуск

Нужен Python **3.11 или новее**. Команды выполняются из папки проекта.

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell не разрешает активацию, используйте
`.venv\Scripts\python.exe` вместо `python`; менять системные настройки не требуется.

Откройте `.env` в редакторе и заполните:

```dotenv
GEMINI_API_KEY=ваш_ключ
```

Ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey).
Файл `.env` исключён из Git. Переменная окружения с тем же именем имеет приоритет.
Существующий `.env` при повторной установке не перезаписывайте.

Проверьте модель в `config.toml`. По умолчанию используется
`gemini-3.5-flash-lite` — выбранная для пилота модель. Доступность и квоты
определяются вашим проектом Google. Автоматического перехода на другие модели нет.

Проверка файлов и запросов **без ключа, зависимостей и обращений к API**:

```bash
python main.py --dry-run
```

Первый настоящий запуск на демонстрационном тексте — два запроса:

```bash
python main.py --input data/lectures/example_dijkstra.txt
```

Для собственной лекции сохраните исправленный текст в UTF-8, например
`data/lectures/lecture_01.txt`, и запустите:

```bash
python main.py --input data/lectures/lecture_01.txt
```

## Другие команды

Все `.txt` в папке, включая вложенные папки:

```bash
python main.py --input data/lectures
```

Один метод:

```bash
python main.py --input data/lectures/lecture_01.txt --methods M1
```

Три независимых повтора каждого метода:

```bash
python main.py --input data/lectures/lecture_01.txt --repeat 3
```

Другая модель, общий предел слов и папка результатов:

```bash
python main.py --model gemini-3.8-flash --max-words 400 --output results/pilot
```

```bash
python main.py --help
```

Один повтор = один запрос на метод и лекцию. Для 3 лекций, 2 методов и 3 повторов
потребуется 18 запросов без учёта повторных попыток после серверных ошибок.
Программа выводит план до начала работы. Повторный запуск команды создаёт новый
эксперимент и снова вызывает API; автоматического продолжения старого запуска нет.

## Что делают методы

**M1:** лекция целиком + простая инструкция составить краткий конспект.

**M2:** лекция целиком + требования сохранить определения, формулы, алгоритмы,
условия и выводы, используя только исходный материал.

Шаблоны находятся в `prompts/m1.txt` и `prompts/m2.txt`. Ограничение объёма,
правило интерпретации входа как учебного текста и язык одинаковы. Каждое обращение
независимо, без истории предыдущих ответов, поиска и внешних инструментов.

Инструкция «не более N слов» не является жёстким ограничением API. Фактическое
число слов сохраняется вместе с флагом `within_word_limit`. Программа не обрезает
конспект и не исправляет ответ автоматически. Перед основным экспериментом нужно
проверить сопоставимость длины ответов и зафиксировать параметры на пилотном наборе.

`max_output_tokens` — отдельный технический предел генерации, который может
затрагивать и thinking-токены. Обрезанные ответы получают статус `truncated`.
Температура по умолчанию не передаётся: используются настройки сервиса. Если её
указать в TOML, она будет одинаковой для обоих методов. Параметры, версия SDK и
возвращённая сервером версия модели сохраняются, но это не гарантирует побитового
совпадения повторных ответов или неизменности облачной модели.

## Результаты

Каждый запуск создаёт отдельную папку, например:

```text
results/<время-UTC>_<идентификатор>/
  manifest.json                    # план, настройки, окружение, состояние запуска
  metrics.csv                      # статистика каждого результата, открывается в Excel
  lectures/0001_lecture_01.txt      # снимок исходного текста
  prompts/M1.txt                   # снимки шаблонов
  prompts/M2.txt
  results/
    0001_lecture_01_M1_r01.json     # запрос, ответ, хеши, статистика, ошибки и попытки
    0001_lecture_01_M1_r01.md       # конспект
    0001_lecture_01_M1_r01.response.json  # ответ SDK без HTTP-заголовков
    ...
```

JSON записывается после каждого результата; CSV дополняется сразу.
Имена не пересекаются даже при одинаковых именах лекций в разных папках.
Временные отметки — UTC с указанием смещения; длительности — секунды.
Полный формат для остальных участников описан в [docs/RESULT_FORMAT.md](docs/RESULT_FORMAT.md).

Программа автоматически считает **число слов, отношение длины конспекта к длине
исходника, время, число попыток и расход токенов**. Слово здесь — непустая
последовательность символов между пробелами, не лингвистическая единица.
Отношение объёмов может быть больше 1, особенно на коротком демонстрационном тексте.

`elapsed_seconds` включает ожидания между запросами и повторами;
`api_seconds` — суммарное время попыток API, включая неудачные.
Для сравнения скорости при наличии повторов анализируйте журнал попыток.
Токены записываются из `usage_metadata`, не оцениваются по длине текста.
Если сервер не вернул статистику неудачной попытки, её расход неизвестен;
usage результата относится к финальному полученному ответу и не включает
неизвестный расход неудачных попыток. В CSV отсутствующие значения остаются пустыми.

**Precision, Recall, F1 и фактическая достоверность пока не рассчитываются.**
Для них третий участник подключит эталонную разметку и отдельный модуль оценки.
Программа уже сохраняет исходники и конечные конспекты для этого. Проверка
достоверности внутри будущего M4 не должна заменять внешнюю оценку всех методов.

## Ошибки и квота

- Между началами запросов выдерживается интервал из `config.toml` (по умолчанию 5 с).
  Это не гарантия соблюдения TPM/RPD, особенно при длинных лекциях или других
  программах, использующих тот же проект.
- При HTTP 429, 400, 401, 403 или 404 результат ошибки сохраняется и весь запуск
  останавливается. Проверьте квоту, ключ, доступность модели или параметры.
- Серверные ошибки 500/502/503/504 повторяются до `max_retries` раз. Каждая попытка
  записывается. Сетевые таймауты автоматически не повторяются.
- Пустые, заблокированные и обрезанные ответы не считаются успешными.
- Ctrl+C завершает запуск с сохранением уже полученных результатов.

Коды выхода: `0` — успех или dry-run; `1` — ошибка входных данных/настроек;
`2` — ошибки генерации, блокировка или обрезка; `130` — прерывание пользователем.
В dry-run конспектов нет, токены и метрики ответа остаются пустыми.

## Распределение работы

1. **Первый участник:** API, M1/M2, запуск и журнал результатов — реализованы здесь.
2. **Второй участник:** M3/M4. Использует тот же формат результата и общие настройки;
   добавляет сегментацию, извлечение, объединение и проверку по источнику.
   Текущий runner выполняет один запрос на метод, поэтому многоэтапные методы
   потребуют расширения runner и суммирования usage всех этапов.
3. **Третий участник:** эталонные элементы, сопоставление с конечными конспектами,
   метрики качества и сводные таблицы. Подготовку и проверку эталонов делят все трое.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты не требуют ключа и не отправляют запросы в Google. Они проверяют сохранение
данных, независимость запросов, повтор серверных ошибок, остановку по квоте,
неполные ответы и интеграцию с настоящим SDK через подменённый HTTP-транспорт.
